# Version 0.5: iPad installation and private owner review

This is a staging candidate, not a completed academically verified FR archive.
The plugin code, private content package and academic publication are separate.
No Hostinger installation or staging database was inspected during this work.

1. In GitHub, open the V0.5 pull request, then its successful **Test and build WordPress plugin** run. Under **Artifacts**, download **ca-final-command-center-0.5.0**. In iPad Files, tap the outer artifact ZIP once. Find the inner **ca-final-command-center.zip**; upload that inner ZIP without unpacking its plugin folder.
2. Before installing, take a staging database/files backup using your normal hosting controls. This task does not access those controls for you. Keep the old plugin ZIP and the matching database backup together. Pause academic editing during the update.
3. On your password-protected staging site, open WordPress Admin → Plugins → Add New Plugin → Upload Plugin → Choose File. Select **ca-final-command-center.zip**, install, and choose **Replace current with uploaded**. Activate if necessary. Do not delete academic tables or use any reset/import-database utility.
4. Confirm Version **0.5.0** and open **CA Final Command Center → Getting started**. Existing IDs, accounts, notes, bookmarks and progress must still be present. Old MCQ records remain in storage but are excluded from subjective practice. Unknown/mixed formats remain private until classified.
5. Open the separately supplied **private Google Drive delivery folder**, download the FR content ZIP, and tap it in Files to extract it. Read **READ-FIRST.txt**, **coverage-report.json**, **exceptions.json** and **import-order.json**. The plugin ZIP contains no question archive.
6. In **Question Review Studio → Import hierarchy / research JSON**, upload files from **taxonomy-imports**, one at a time in numeric order. Inspect validation and existing-wording warnings, then tap **Apply validated decisions / draft batch**. New headings start as drafts. Existing keys, wording, approvals and IDs are retained. In Connected Academic Manager, check and publish the correct edition and its official parent paths before using them in student navigation.
7. Import the numbered **imports/studio-drafts-*.json** files the same way. Batches are bounded and idempotent; retrying an unchanged batch adds no duplicate records. If an existing candidate conflicts, **Retain existing records and preview only new drafts** preserves it. The per-record **Enrich missing authorised private content** control adds only missing private content after explicit confirmation, retaining its identity, tags, notes and original AI evidence. Differing existing text/answer identities require manual comparison; nothing is silently replaced.
8. Open **Publication Rights → New permission**. Enter the actual authority, written reference/date, publisher, covered ICAI material/periods/uses, attribution and restrictions. For the lifetime duration you reported, leave expiry blank. Select **All periods** only if the written permission actually covers them. The optional permission PDF is stored in the private database, never the public Media Library. Activate the scope only after checking it. Record its ID on covered Studio records. Changing/revoking a scope withdraws its linked questions for review.
9. Open one **SUBJECTIVE** draft. Read the entire question and its proposed answer together. Edit text directly in the authorised rich preview, or use the optional safe HTML fields. Check every amount/table, shared scenario, subpart, PDF page, answer document/series, historical edition and topic path. Use **Use proposed draft path** only when its source-supported nodes exist; this saves a draft, not an approval. Select the detailed topic/subtopic and primary path. Resolve each blocking exception only after checking its evidence and record your correction/disposition in notes. **Save Corrections** first.
10. Choose **Needs Review**, **Publish** or **Reject**. Publish validates source/attempt/edition, boundaries, tags, exact answer identity, current full text, permission and unresolved conflicts in one transaction. It records the detailed approval fingerprints internally. A blocker is explained and leaves the item Needs Review. A successful Publish immediately makes that eligible occurrence available; no new ZIP or deployment is needed. Reject withdraws visibility while retaining its ID, history and student progress.
11. For Excel, review **Approval Decisions** in the private workbook. Select **Needs Review**, **Publish** or **Reject**; do not change protected IDs, hashes or revision cells. The matching JSON must first be imported. Initial archive workbooks validate only untouched revision 1 records and exact question/answer HTML hashes. If WordPress has a newer correction, export a fresh workbook from selected Studio rows. Upload → Validate → inspect conflicts → Apply. Editing Excel alone never changes WordPress. If a question exceeds Excel's cell limit, its complete formatted text is in **details/<Stable ID>.html** in the private package.
12. Test with two approved staging test students using the existing access process. Search a topic directly, select a chapter and inspect its topics, and select an available attempt independently. Open a published subjective card; its full question and official ICAI citation should appear. The answer must be absent initially, fetched only on **Show Answer**, and cleared on **Hide Answer**. Check that notes, bookmarks and practice status remain separate for both students. Check My Dashboard, My Practice, dark/light preference and MCQ Practice → Coming Soon on your actual iPad.

## Missing official source files

The private inventory identifies every catalogued Drive file and separately lists additional official study/examination resources and access exceptions. For a missing original: open its verified ICAI URL in Safari → download/save the PDF → use the Files share sheet to save it to your authorised private FR Drive research folder. Retain its filename and edition/attempt. Do not change sharing to public. Provide the private folder link for the next resumable worker run. No Drive background synchronisation is promised or installed.

## Rollback

Deactivation never deletes data. To reverse only an imported research batch, use Studio **Hold entire batch**; its publication is withdrawn while IDs and student records remain. Resuming returns drafts, never automatically republishes. Do not reinstall V0.4.1 against schema 5: downgrade is refused. A complete software rollback requires restoring the paired pre-upgrade database/files backup while editing is paused; retain a current backup first so later student activity is not lost.
