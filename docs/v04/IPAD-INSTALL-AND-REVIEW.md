# iPad: private staging installation and owner review

The final v0.4 plugin ZIP contains code only. It does not contain real questions, PDFs, student accounts, payments or approved taxonomy. The separate private research workbook/transport is not part of installation. Do not install component PR artifacts as the final release.

1. Keep staging password protection. In Hostinger yourself, take a complete staging files + database backup; retain the old v0.3 ZIP. No Hostinger action was performed by this development task.
2. Download `ca-final-command-center.zip` from the final delivery or the final PR's successful **Test and build WordPress plugin** Actions run. In GitHub → Actions → that run → Artifacts, download **ca-final-command-center-0.4.0**. GitHub's artifact is an outer ZIP: tap it in iPad Files to extract, then locate the inner `ca-final-command-center.zip`. Do not upload the outer artifact container.
3. Open staging WordPress Admin → Plugins → Add New Plugin → Upload Plugin → Choose File → the inner ZIP → Install Now → **Replace current with uploaded**. Verify it is the same `ca-final-command-center` folder/plugin and Version 0.4.0. Activate if necessary. Do not delete the old plugin or database tables first. If WordPress reports a migration/extension error, stop and retain the backup; do not recreate tables manually.
4. Open **CA Final Command Center → Question Review Studio**, **Connected academic manager**, **Topic proposals**, **Student access**, and **ICAI Resources**. Verify your old question IDs, users, notes and progress still exist. New display gates intentionally hide records without the new approvals. The migration report explains this change.
5. Visit `https://YOUR-STAGING-DOMAIN/?cafcc_view=explorer`. The old dashboard shortcode still works. Other routes use `cafcc_view=login`, `register`, `forgot`, `pending`, `account`, `membership`, `dashboard`, `practice`, `resources`, `trends`, `planner`. For normal page slugs, add `[cafcc_portal view="explorer"]` (or another view) to your chosen page. Optional administrator API `POST cafcc/v4/admin/pages/prepare` creates **drafts** only. The release does not publish pages or replace your navigation/theme.
6. In **Student access**, migrate each existing test Subscriber explicitly: either request a fresh verification email, or check the identity/email confirmation only after you have verified it. Apply an appropriate plan/expiry as administrator. No automatic membership is granted. Test new registration with an address you control: email link → Confirm Email → Pending Approval → your manual grant → student can practise. Verify actual mail delivery and password reset on staging. No payment is needed or active.
7. In **Topic proposals**, preview the next missing batch, inspect it, then apply as Draft. Repeat as needed. Review source evidence, edition and official/editorial origin in the connected manager. Do not bulk-approve editorial trees or map January 2026 to May 2026 onwards. AFM and many other chapters have no ICAI-numbered units; a blank Unit can be valid. Draft/unavailable concepts intentionally do not appear as verified student suggestions.
8. Keep `CA-Final-Private-Research-Review.xlsx` in private iPad Files. Its 139 provisional records and inventory are research context, not WordPress decisions. Inspect the FR corrections, AFM conflict, boundaries and answer candidates against your authorised PDFs. Resolve missing historical edition/topic IDs before publication. No copied question or answer prose is included.
9. Upload a small `studio-drafts-001.json` batch in Review Studio → inspect validation/duplicate/conflict report → Apply validated draft batch. It remains Needs Review. Choose the applicable edition and reviewed detailed tags, record reasoning and exceptions, inspect source/number/boundaries and exact answer mapping. Use **Save Draft** before approvals.
10. Approve source, boundary/number, classification, answer mapping, rights, question revision and answer revision separately. For new independently authored/licensed content, approve the first three stages and **Prepare Draft Reference** to obtain a QID; attach/review rich question and solution content in **Practice content & rights**, then approve the remaining Studio stages. Original/licensed answer mapping uses the current solution's SHA-256 shown in the panel. Otherwise publish reference metadata + official answer link only. A private PDF's availability is not reproduction permission. Final **Publish When Eligible** is a separate deliberate action.
11. Excel is optional. Select up to 100 Studio rows → **Download Review Excel** → edit **Approval Decisions** in Excel on iPad → save `.xlsx` → upload in Studio → inspect all validated changes/conflicts → apply. Use corrected existing Node IDs and explanation for classification corrections. A workbook edited offline does nothing until you apply it. Re-export after any intervening WordPress edit; stale/reused/expired workbooks are rejected. Do not remove sheets or add formulas/macros/external links. Use Studio for full rich detail and records too long for a cell.
12. Test as two approved students in separate sessions: search a concept directly, clear chips, combine source/attempt, view a permitted question, tap Show Answer, save distinct notes/bookmarks/status and verify isolation. Answers must remain absent until tapped. Check phone/iPad portrait/landscape and keyboard navigation/reduced motion. Use your own original demonstration question or the authored test previews; automated fixtures are deliberately not installed into staging by the ZIP.

Batch Hold is available in Studio's Batch hold/resume controls. Enter its exact batch key. It atomically withdraws student publication, retaining IDs/evidence/history/student records. Resume returns drafts, not published records. A complete staging rollback restores the matched pre-upgrade database and files backup together. Do not simply run v0.3 against the newer database. Do not upload the private research ZIP, source PDFs, inventory, credentials or workbooks into public Media/GitHub.

First owner pilot: review the source-specific FR January 2026 Q6–9/Q11–14 and resolve whether the AFM securitisation corrections refer to Q1(I–IV). Confirm private copying/storage permission for the wider archive before authorising more extraction. Neither this installation nor passing tests constitutes academic approval.
