# iPad installation and first real FR reference

Keep staging password-protected. Nothing here has been deployed or academically approved for you.

1. Back up staging **files and database** yourself and retain the v0.4 ZIP. Download `ca-final-command-center.zip` Version 0.4.1. If downloading a GitHub Actions artifact, extract its outer ZIP in Files first; upload the inner plugin ZIP.
2. In staging WordPress → Plugins → Add New Plugin → Upload Plugin, select that ZIP → Install → **Replace current with uploaded**. Do not delete the existing plugin/data first. Confirm Version 0.4.1. Schema remains 4; existing user/question IDs and practice records are retained.
3. Open CA Final Command Center → **Getting started**. Its counts describe your current installation. If Studio is empty, it will instruct you to import the private JSON. The diagnostics and guide do not publish anything.
4. Download the small private FR pilot. Keep it in private Files, not public Media or GitHub. `studio-drafts-001.json` is the only research JSON to upload. Other evidence/result JSON files are for reading, not importing. The five records are Q6, Q7, Q8, Q9 and Q14. They exclude FR Answer 19 and AFM conflicts.
5. In **Connected Academic Manager**, select the historical FR edition applicable to May/September 2025 and January 2026. Inspect the official source listing/date yourself. Use the source-reviewed confirmation to publish its official headings only when you have verified them. Do not substitute May 2026 onwards. The historical Chapter 9 is Ind AS 115; no numbered unit is required for it.
6. Connected Academic Manager → CSV imports → type **hierarchy** → choose `pilot-hierarchy.csv` → Validate & preview → Import validated draft batch. Four editorial topic proposals are created as drafts. In the taxonomy collection, find each topic by title; confirm its historical edition and Chapter 9 parent, correct it if needed, and explicitly set Reviewed/Verified and Published only after your academic review. These labels are editorial navigation, not official ICAI unit headings.
7. Open **Question Review Studio** → Import research batch → select `studio-drafts-001.json` → inspect validation, duplicates and conflicts → **Apply validated decisions / draft batch**. You should see five Draft/Needs Review records. Existing conflicting corrections will not be overwritten. The packet also works with v0.4's original importer; v0.4.1 adds the clearer diagnostics and mapping button.
8. Open Q6. Tap **Use proposed draft path** to resolve the supplied edition/topic keys to your own database IDs. If a node is missing, follow the displayed CSV import instruction. This button saves a draft; it does not approve it. Review the edition, classification, source scheme and reasoning; Save Draft after changes. The initially supplied scheme description explicitly asks for owner confirmation—replace it with your verified scheme description.
9. Inspect your authorised PDF: Q6 begins on PDF page 3, with its shared MCQ scenario coordinates in the boundary evidence; the answer-marker candidate is page 13. Open the actual question and answer before confirming. Review uncertainties and record your disposition in My private notes. An automated marker match is not answer verification.
10. Approve **Source Identification**, **Boundary & Number**, **Classification**, **Answer Mapping**, **Publication Rights**, **Question Revision** and **Answer Revision** separately. Choose **reference_only** rights and keep its reference-only basis. No copied ICAI question/answer text is supplied. For these reference-only records, content-revision approval confirms there is no public full-text body to reproduce. Finally tap **Publish When Eligible**. If blocked, the panel shows the next required action.
11. Use an approved test student with a current manual entitlement. Existing Subscribers are not automatically granted access; verify them individually in Student access. Open Question Explorer, search the reviewed historical topic or Ind AS 115, and choose the January 2026 path. The reference should show **RTP · FR · January 2026 · Q6 · Ind AS 115** and link to the recorded official ICAI PDF. Show Answer should fetch only the verified official answer link/location, not copied answer text.
12. Review the remaining four separately. Do not approve the whole pilot merely because the Q6 software test passed. Academic approval, rights and exact answer checks are your decisions.

## Test your own formatted Show Answer example

The real ICAI pilot is reference-only. Keep an authored demonstration separate. The delivery includes an original demo draft JSON, original hierarchy CSV and original question/solution HTML; no ICAI past-paper text is used.

Import/review the original hierarchy in its indicated FR May 2026 edition, then import `authored-demo-drafts.json`. Open it, use proposed draft path, inspect the independently authored identity and approve the first three stages. **Prepare Draft Reference** allocates a permanent QID without publication. In Practice Content & Rights, attach `authored-question.html` and `authored-answer.html` to that QID as separate question/answer entries, record Original rights and project authorship, and approve their saved revisions. In Studio's permitted-content source evidence, copy the current answer body SHA-256. Set Answer presentation to Our independently authored solution, supply that hash and an original solution location, Save Draft, then approve the remaining stages and final publication. No official answer URL should be invented for it. The scheme, source type Other, reference ORIGINAL-1 and author labels distinguish this example from an examination question; the official URL is syllabus background only.

Question text should be visible immediately. Answer content must be absent until Show Answer; Hide Answer must clear it. Test with two separate approved accounts: use different notes/status/bookmarks and confirm they remain separate. My Practice shows each student's own saved records/bookmarks/revision queue; My Dashboard is a separate saved-activity summary.

## Display checks and rollback

Use the sun/moon control at the top-right. It initially follows system preference and remembers your choice across portal views. Check light/dark, selected and disabled dropdowns, autocomplete, portrait/landscape and keyboard focus on your actual iPad. Automated Chromium/WebKit engine results do not certify the native Safari popup on your device. Admin appearance is unaffected.

Browse Syllabus shows only reviewed published paths, including paths with no questions; those display No verified questions available yet. Practice Questions filters availability. Unreviewed editorial drafts remain private. Dashboard/My Practice/Explorer are separate views.

Excel is optional: download a fresh server-issued Review Excel from Studio, edit Approval Decisions, upload → validate conflicts → apply deliberately. Editing the private research workbook does not change WordPress. Stale/reused workbooks cannot overwrite newer corrections.

To withdraw an incorrect pilot, use Studio's Batch hold/resume controls with its manifest batch key; IDs and student records remain. For a full rollback, restore the matched pre-upgrade database and files backup together. Do not delete tables or simply run older security gates against a newer database.
