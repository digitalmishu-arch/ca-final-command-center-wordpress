# iPad: upload, preview, publish

Use the password-protected **staging** site. This release does not access or change hosting. Keep a matched database/files backup before upgrading.

1. Download the **ca-final-command-center-0.6.0** Actions artifact. In Files, unzip the outer download. WordPress → Plugins → Add New → Upload Plugin: select its **inner `ca-final-command-center.zip`**, replace the existing plugin and activate. Do not uninstall or delete data.
2. Open **CA Final Command Center → Upload Questions**. Select the compact, previously delivered **FR-Jan2026-v0.5.2-Academic-Import-r016.zip**. Keep it zipped. No replacement academic package is needed. Do not upload the research evidence archive or PDFs into Media.
3. Tap **Upload & Preview**. Inspect the actual counts and representative full questions/answers. If the package includes a new source-wide permission declaration, confirm its displayed scope once. An existing active declaration is reused without a scan or repeated individual permission choices.
4. Choose **Save as Drafts**, or **Publish All**. The importer commits dependencies in order and saves checkpoints. Publication prepares source-backed historical paths and separate inferred search tags automatically; there is no manual edition → chapter → topic approval chain.
5. Inspect the concise publication preview. Tap **Confirm Publish All** once to authorise the selected eligible revisions **provisionally**. This does not certify that you individually verified every question, answer or topic. Technically blocked rows remain drafts. Unresolved/withdrawn solutions stay **Answer Pending** rather than showing an unrelated answer.
6. Open **Question Library**. The current dataset uses exact package membership, not a search for January 2026. Its total is the package's retained/new records, including any blocked drafts. Use Historical drafts, Archived/superseded, All records or a specific package deliberately. Select Current Page or All Filtered before a bulk action; the confirmation shows the exact selected count.
7. Search a stable Question ID → **Edit**. Correct selectable question/answer text and academic tags, then **Save & Republish**. Previous content, author/timestamp, question/occurrence IDs and student history remain. **Withdraw Answer** keeps the question available with Answer Pending. Revision history can restore an earlier version as a new draft. Unpublish first before archiving a published record; restoring an archive does not silently publish it.
8. Test an entitled student: direct `Ind AS 109`, `Financial Instruments`, `SA 520` or topic search; source/attempt/series filters; Question/Answer/Both; stopwatch; private notes/tags/bookmarks/highlights; Dashboard and My Practice. Audit examples in public automated tests are independently authored, not ICAI past questions. Check on your actual iPad Safari: automated viewport/WebKit tests do not replace device acceptance.

**Interrupted?** Upload Questions → Resume saved work, or upload the identical ZIP again. Checkpoints and revisions prevent duplicate imports or stale decisions. Do not alter a ZIP under an existing package key.

**Advanced tools:** Settings contains the physical permission register, private source register, standard references and Advanced Academic Tools. Existing audit and detailed classification tools remain accessible. A missing legal scope, corrupted question structure, wrong source identity or unresolvable source edition needs correction; low classification confidence alone does not block the whole bank.

**Rollback:** preserve new corrections/student activity, then restore the matched pre-update database **and** files/plugin backup. Schema 8 is additive. Replacing only plugin code is not a database downgrade. No real publication or entitlement occurs merely by activating the software.
