# January 2026 corrective software 0.5.2

This patch continues PR #12 and the existing January research. It is a software update, not a declaration of academic completeness. No hosting account, live database or production website was accessed. The original RTP IDs, owner corrections and historical edition keys remain intact.

## What changed

The former rights form required a reference/date even when the owner retained a signed physical permission. The new **Publication Rights** declaration accepts **Signed physical authorisation → Owner attestation**. Record the issuing authority, physically retained evidence, publisher, exact examination periods, covered source categories, permitted uses, attribution and actual restrictions/duration. Unknown signature dates, references and expiry may stay blank. A scan is optional. An administrator must explicitly confirm activation. Actor, server timestamp and revisions stay in the private audit trail. No academic approval follows from a rights declaration.

An exact source register distinguishes ICAI hosting, owner-verified ICAI mirror copies and other material. Registering one mirror URL does not whitelist that host. Publication checks require the actual question/answer hashes, roles, target attempt and MTP series. Private Drive IDs are administrator-only. Source changes withdraw affected public records while retaining identities and student activity. Corresponding ICAI-hosted URLs may be entered only when the exact counterpart has been verified.

**Import Academic Package** accepts a compact, JSON-only ZIP. The large research evidence ZIP and plugin ZIP are separate files. Manifest byte lengths, SHA-256, ZIP CRC, safe paths, size/expansion limits and dependency order are checked before preview. No archive is extracted into uploads or Media. Dependencies run in a rolled-back preview transaction, then one owner confirmation authorises the included rights declaration and Needs Review imports. Each dependency item and its cursor commit together; retrying or reuploading the same archive resumes the private checkpoint. Existing corrected IDs, source declarations and scenarios are retained with conflicts. A changed archive needs a new package revision. Proposed taxonomy remains unapproved.

The normal **Publish** decision confirms the owner's comparison of the exact saved question, answer, boundaries, figures, tables and classification. The server retains signed content fingerprints and runs all other checks atomically. This removes a separate repetitive comparison button from the normal workflow. Genuine extraction/answer/table conflicts, unreviewed taxonomy, stale revisions and missing source scope still block publication. Optional Advanced Review remains available. Bulk preview uses prospective confirmation without saving approvals; Apply requires explicit owner confirmation and rechecks frozen revisions. Excel Publish decisions use the same owner review meaning and authenticated validation/apply flow.

## iPad installation and import order

1. In staging, obtain a current **database and plugin/files backup** using your existing backup process. This work does not run the backup or access Hostinger for you.
2. Download the **0.5.2 GitHub Actions artifact**, open its outer ZIP in Files, and find the inner `ca-final-command-center.zip`. WordPress → Plugins → Add New → Upload Plugin → choose that inner ZIP → Install → **Replace current with uploaded**. Do not delete/uninstall the existing plugin.
3. Confirm version **0.5.2**. Existing accounts, entitlements, question IDs, progress, private notes and sessions remain.
4. Download the private **Academic-Import-r009.zip** from the authorised Drive folder. Keep this ZIP zipped. WordPress Admin → CA Final Command Center → **Import Academic Package** → choose it.
5. Inspect the counts, retained duplicates/conflicts, source register and included January-only physical rights declaration. Tick the one confirmation only if it matches your permission. Tap **Confirm and import academic drafts**. Keep the page open until completed. After interruption tap **Resume saved import**, or reupload identical bytes. All academic records remain Needs Review.
6. Inspect **Private Source Register** on that page. The RTP is technically checked; the other six supplied URLs are Owner Verified selections with an explicit retrieval block. Issue periods remain unknown until read from the actual papers. Do not mark an unread file as technically checked.
7. In Connected Academic Manager, inspect the **November 2024** FR edition applicable to January 2026 (`fr-may2025-jan2026`). Review its proposed official headings once. Draft editorial tags remain private. Do not approve all 1,023 proposed headings without checking their evidence.
8. Open **Question Review Studio**. Read the full question and matching answer together, inspect PDF/page/table evidence, correct tags or content, then Save Corrections. Resolve genuine exceptions before Publish. **Needs Review / Publish / Reject** are the normal decisions. Publish confirms your review of the saved revision and makes an eligible occurrence immediately available; no plugin deployment is needed.
9. For a batch, choose **Select Current Page** or **Select All Filtered**, action and **Preview selected count and checks**. Inspect valid/blocked records, confirm your review, then Apply. Only eligible unchanged revisions publish. A blocked row stays private; student history is preserved.
10. For Excel, keep the private owner workbook private. Import its matching academic ZIP first. Upload workbook decisions through Studio → Validate → inspect conflicts → Apply. Existing corrections or newer revisions require a fresh WordPress export. A dropdown selection in Excel alone never publishes anything.
11. Test an entitled student: independent January/source/series/topic filters, clickable PDF badge, Show/Hide Answer, stopwatch, note, tag, Important, bookmark, highlights and personal Dashboard/My Practice. Repeat with a second account to verify privacy. This is your actual staging/iPad acceptance step; disposable browser tests do not replace it.

The fallback remains the eleven numbered taxonomy JSONs, private source/rights registration and one `studio-drafts-001.json`. Prefer the single Academic Import ZIP. Never install a research ZIP as a plugin or upload it to Media.

## Additive migration and rollback

Schema **6 → 7** creates only three InnoDB tables: private source register, academic package jobs and academic package items. No prior academic/student table is dropped, renumbered or remapped. Existing rights rows keep their legacy defaults; no attestation, membership or publication is automatically created on activation. Importing a package is a separate authenticated action. Deactivation preserves data.

Before rollback, save new review corrections and activity. Restore the matched **pre-update database plus plugin/files backup**; replacing code alone is not a validated database downgrade. Never manually lower schema options, truncate tables or delete student rows. The private package report records retained duplicate/conflict decisions and dependency checkpoints.
